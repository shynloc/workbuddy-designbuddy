# 付费 Skill 保护验证

## 1. 三个概念（不能混为一谈）

| 概念 | 含义 | 当前证据 |
|---|---|---|
| **Paid Skill** | 付费销售机制 | `OBSERVED`（UI 文案） |
| **Encrypted Skill** | 平台提供的加密选项 | `OBSERVED`（仅 UI 文案） |
| **Source Protection** | 实际能否防止用户或其他 Agent 读取、复制、提取原始实现 | `UNVERIFIED` |

在没有实测结论之前，DesignBuddy 的对外材料只使用 **Paid Skill** 这个说法。包括市场介绍、宣传文案、README，都**不写** "Encrypted Skill"、"源码加密"、"防复制" 等说法。

这份验证还要回答一个**架构问题**（D-03）：加密后，DesignBuddy 预置的确定性生成器还能不能执行并输出产物。

> 读不到原始源码，不等于不能执行受保护的生成器。

## 2. 已知信息（仅限 UI 文案层面）

来源：2026-10-10 抓取的 open.workbuddy.cn 前端 i18n 文案。证据等级为 `OBSERVED (UI text only)`。

| 文案 | 能证明什么 | 不能证明什么 |
|---|---|---|
| "已开启（付费能力必须加密，不可关闭）" | 付费资产在配置界面上有一个强制开启的"加密"开关 | 加密的方式、加密在哪一层、加密的效果 |
| "会对资产内容进行一定技术防护，但无法完全避免泄漏" | 平台自己声明保护不完整 | 用户能看到什么、看不到什么 |
| "且用户不可使用自定义模式调用" | 存在一种名为"自定义模式"的调用方式，开启加密后用户不能用它调用 | "自定义模式"具体指什么，以及它对 DesignBuddy 交互的影响 |

> **更正**：此前的对话中，我把这些文案概括为"付费 Skill 必须加密"，并把它当作事实使用。现在改为：**UI 上存在这个开关（已观察到），实际效果未经验证。**

## 4. 影响矩阵

| 结论 | 对 DesignBuddy 的影响 |
|---|---|
| Agent 不能读取 references | DesignBuddy 无法采用 Progressive Disclosure，方法论必须放进 SKILL.md 正文或其他可见的载体 → **重大架构调整** |
| scripts 不能执行，或不能读取同包文件 | 生成器必须是自包含的单个脚本（数据内嵌在代码中），否则降级为 Agent 生成（D-03 已按这种情况准备） |
| 不能把模板原样复制到工作目录，但 P-GEN-RENDER 为 PASS | **保持默认 Compiler 架构**（产出本来就是渲染出来的，不是复制） |
| 脚本能执行，但读不到自身资源 | 把模板和数据内嵌进预置生成器的代码中（仍然是确定性构建） |
| 脚本不能执行 | 评估替代方案；服务端编译需要产品负责人批准；Agent 现场生成只作为最后的降级（D-03 CONDITIONAL） |
| 用户能看到全部原文 | 对外不提保护；商业壁垒完全依靠方法论、持续更新和服务（本来就是主要策略） |
| "自定义模式"限制影响自然语言触发 | 调整 description，以及用户引导话术 |

## 5. 对外文案规则（在结论出来之前一直有效）

| 允许 | 不允许 |
|---|---|
| "付费技能"、"Paid Skill" | "加密技能"、"Encrypted Skill"、"源码不可见"、"防破解" |

如果验证证明平台提供了明确的保护机制，再按验证结论和官方表述调整对外文案，并在本文记录依据。
