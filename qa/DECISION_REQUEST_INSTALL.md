## 2. 三个选项

| 选项 | 用户体验 | 风险 | 我的建议 |
|---|---|---|---|
| **A. 只用平台路径（H3b/H4）** | 品牌系统生成后，用户把 ZIP 拖进对话或在 UI 中导入，一次操作 | 最低。安装完全由平台负责 | **先验证 A**：如果 H3b 或 H4 可行，V1 就用它 |
| **B. 受控的 H5（用户确认后由 DesignBuddy 写入用户级 skills 目录）** | 真正的"对话内一键安装" | 依赖平台目录结构和注册机制；平台升级后可能失效；需要卸载和回滚机制 | 只有 A 不可行或体验不可接受时才考虑。需要满足下面第 3 节的全部条件 |
| **C. 只交付 ZIP 和文字指引** | 最差 | 最低 | 作为兜底，保留 |

## 3. 如果选择 B，我会遵守的条件（需要你逐条认可）

1. 每次安装前展示摘要，并取得明确确认（沿用现有的 INS-006 流程）。
2. 目标目录**不靠猜测**：只使用 designbuddy-qa 或 designbuddy 自身所在目录的上级目录。也就是说，只写到平台已经用来安装 Skill 的同一个位置。
3. 绝不覆盖：同名目录存在时，必须走"升级确认"。升级前把旧版本完整备份到 Workspace 中。
4. 先在临时目录中完整写入，然后整体移动，避免出现装了一半的状态。写入后立即运行 selfcheck，结果必须是 MATCH。
5. 生成安装凭证（安装了哪些文件、各自的哈希、备份位置），并提供 `uninstall` 命令。该命令只删除凭证中列出的文件。
6. 不修改任何其他 Skill，不碰平台写入的 `_user_meta.json`。
7. 安装后在新会话中验证平台能识别并调用。如果平台不识别，就回滚并告知用户。
8. 作为"实验性"能力，默认关闭，必须由用户明确选择开启。
